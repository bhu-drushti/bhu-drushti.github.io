The Problem

Maharashtra's Girdawari — a seasonal crop survey across 2.3 crore plots — is the legal foundation for subsidy disbursement, PMFBY insurance, disaster compensation, and Kisan Credit Card lending. Every error or fraud cascades into every downstream decision. Yet it is executed entirely by hand.

Without Bhu-Drushti

A Krishi Sahayak in Baramati taluka — post-Kharif, October

  • 3,200 plots across her Circle need physical verification
  • 8 Krishi Sahayaks, 15 min per plot = 100+ working days
  • No way to know which plots actually need a visit
  • Every plot treated as equal priority

Result: physically impossible to complete verification within the seasonal window.

With Bhu-Drushti

Same Krishi Sahayak, same October morning

  • Satellite has pre-scored all 3,200 plots overnight
  • She opens a prioritised queue of 4 flagged plots
  • Field visits confirmed with geo-tagged photo evidence
  • Remaining 3,196 auto-confirmed with satellite audit trail

Entire Circle verified within the window. She is no longer the bottleneck.

Satellite crop data from ESA Sentinel-2 (free, 10m resolution, every 5 days) already covers every plot in Maharashtra. Bhu-Drushti is the missing reconciliation layer.

Four Integrated Capabilities

None of which exist in the Girdawari workflow today.

🛰️

Satellite Pipeline

GEE Python API clips Sentinel-2 imagery to plot boundaries. Same code processes 10 prototype plots or all 2.3 crore Maharashtra plots without change. Cloud cover > 40%: auto-flagged for mandatory Krishi Sahayak visit.

⚖️

Risk Scoring Engine

NDVI range matching (Phase 1), pixel-count area check (Phase 2), and DTW time-series classification (>84% accuracy for Indian Kharif crops). Node.js + PostGIS on Docker.

📱

Krishi Sahayak Mobile App

React Native with expo-sqlite — full field day with zero internet. Plot polygons via turf.js on pre-loaded cadastral data. Works on budget Android phones.

🗺️

District Dashboard

Progressive Web App on any modern browser — no install. Leaflet.js interactive map with PostGIS overlays. Role-gated access per officer scope. NDVI change detection for disaster damage.

MVP Status

Working prototype — live demo using real Sentinel-2 data, Malegaon Khurd village, Baramati taluka, Kharif 2024.

✓
Satellite Pipeline — Validated

GEE Python pipeline live. All 10 plots returned NDVI 0.64–0.79, consistent with healthy Kharif vegetation. Plot boundaries digitised from Mahabhunaksha cadastral data.

✓
Risk Scoring — Signal 1 Operational

NDVI range matching produces 0–100 scores. Demo output: 6 auto-confirmed, 3 flagged, 1 escalated. DTW time-series classification staged for Phase 2.

✓
Krishi Sahayak Mobile App — Mode B (Verification Queue)

Risk-sorted queue of 4 plots, offline-first SQLite, GPS accuracy gate ≤ 15m, mandatory geo-tagged photo before verdict. Demo Mode at hackathon venue.

✓
District Dashboard — Basic

Leaflet map with plot polygons coloured by satellite crop classification. Risk summary panel. NDVI disaster change detection demonstrated with simulated pre/post event data.

✓
Backend — Self-Contained

Node.js (Express) + PostGIS on Docker. Three REST endpoints: plot queue, verdict upload, NDVI delta heatmap. Zero government API dependency in Phase 1.
